# Archive — sélection des alertes et worker FCM

Essais locaux du 13 octobre 2026. Les résultats ci-dessous décrivent cette
exécution historique. Pour les commandes actuelles, suivre le
[guide de tests](TESTING.md).

## Corrections vérifiées

- Sélection PostGIS avec le curseur de publication : signalement, historique
  et tâches FCM sont écrits dans la même transaction.
- Un seul contrat `AlertRecipient` : utilisateur, distance minimale et appareils.
- Worker HTTP v1 sans retry de transport ; reprises persistées dans `notifications`.
- Ordre de verrouillage partagé par les workers et la désactivation d'appareil.
- Payload commun Python/Flutter avec `alert_id` stable et valeurs FCM en chaînes.
- Reprise après arrêt brutal avec les mêmes identifiants.

## Résultats consignés

Base PostGIS éphémère sur le port 55433, sans données de production.
Le transport FCM était simulé ; aucun push réel n'a été envoyé.

Les cas couverts incluent rayon de 18 520 m, précision GPS, consentement,
suspension, multi-appareils, rollback, idempotence, concurrence, renouvellement
de token, erreurs FCM, expiration et purge sans perte d'historique.

## Limites

La réception FCM/APNs et l'affichage en arrière-plan restent à tester sur
appareil. `sent` signifie acceptation par FCM. Un crash entre cette acceptation
et le commit peut entraîner un nouvel envoi. Les verrous SQL restent détenus
pendant l'appel réseau : mesurer cette attente avant d'augmenter le débit.
