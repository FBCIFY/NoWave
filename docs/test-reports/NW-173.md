19 octobre 2026. Branche parente : feature/NW-172.

## Reproduction

Une `auth.CertificateFetchError` injectée dans le vérificateur aboutissait à
HTTP 401 au lieu de 503 : test exécuté avant correction, 1 FAIL / 7 PASS.
Le défaut est le `except Exception` du chemin mobile, présent sur origin/dev.

## Résultat et revues

Les certificats, transports et erreurs fournisseur répondent maintenant 503,
avec le code public `authentication_unavailable`. Un token invalide/expiré/
révoqué ou une identité supprimée/désactivée reste refusé en 401. L'initialisation
est également couverte par la classification des pannes. Les erreurs inattendues
ne sont plus déguisées en mauvais jeton. Aucune URL, clé ni token n'est exposé.

- Suite complète API/unitaire : 660 PASS ; Ruff et diff whitespace : PASS.
- Tests : panne puis reprise, certificats, délais réseau, erreurs fournisseur,
  identité invalide, erreur de programmation, enveloppe HTTP publique.
- Revue fonctionnelle : codes 401/503 distincts ; reprise sans changement du
  token ; contrôles de rôle, profil et suspension conservés.
- Revue technique : exceptions SDK explicites, initialisation dans le périmètre
  protégé, messages neutralisés, pas de capture générale d'Exception.
- PostGIS local : BLOCKED (daemon Docker absent), aucun changement SQL.
- Recette Firebase/VPS : NOT RUN. Les pannes sont injectées dans les tests.

Référence SDK : https://firebase.google.com/docs/reference/admin/python/firebase_admin.auth
Environnement : Linux/WSL, Python 3.14, firebase-admin 7.6.0 ; CI Python 3.12.
