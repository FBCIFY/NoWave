# NW-213 — Images des badges Mapbox Android

Base : `origin/dev` `06b2eea90bb2203b3d50d09fc03866ed5bee7cfb`.
Ticket : https://linear.app/blueway/issue/NW-213

## Contrat réellement consommé

Le lockfile verrouille `mapbox_maps_flutter` 2.30.1. La structure générée
`MbxImage` annonce des pixels RGBA prémultipliés. Mais `StyleController.kt`,
lignes 683–703 du plugin installé, appelle `BitmapFactory.decodeByteArray` puis
`bitmap.config` sans vérifier le résultat. Le RGBA brut n'est pas une image
encodée : le décodage retourne null et cause la NPE observée sur LGN LX1.
Le pont iOS de cette même version utilise `UIImage(data:)`, également un
consommateur d'images encodées ; cette inspection n'est pas une validation iOS.

`ReportMarker.paint` retourne maintenant un PNG. Le dessin, les trois catégories,
les couleurs et icônes, l'alpha, les dimensions 120×120 et la densité 3× sont
inchangés. Les images encodées restent mises en cache et sont réenregistrées à
chaque style. Badges ordinaires et sélection réutilisent le même producteur.
Aucun changement des sources MVT, du clustering, des transitions ou du suivi GPS.

## Limites

La fixture locale des marqueurs ne valide pas le réseau marin. Android Release
refuse son URL loopback HTTP (ERR_CLEARTEXT_NOT_PERMITTED) ; ces erreurs sont
attendues et ne sont pas comptées comme succès des couches marines. Le vrai
rendu des marqueurs et les interactions natives sont testés avec GeoJSON en
mémoire. Le regroupement backend est conservé/testé automatiquement ; la forme
regroupée de cette fixture n'est pas une preuve de clustering backend natif.

La cible normale utilise exclusivement le backend distant pour les données
métier et marines ; aucune modification de `.env.json` ni assouplissement réseau
Release. Les 503/429 marins de production restent observables tant que NW-212
et NW-214 ne sont pas déployés. Aucun test iOS réalisé ni revendiqué.
Aucun faux danger créé en production. Aucune fusion ni déploiement effectué.
